# 意图识别与分类训练专题设计

## 背景与目标

现有教程已经介绍监督学习、分类、标签、模型路由、微调数据和评估集，但这些知识分散在不同阶段，还没有形成可运行的意图分类训练闭环。

本次扩展在“阶段十六：微调与模型定制”中新增意图识别专项，使学习者能够完成以下流程：

```text
定义意图体系 -> 标注样本 -> 校验并拆分数据 -> 训练分类器
-> 预测与拒识 -> 计算分类指标 -> 分析错误并回流样本
```

专题面向已有应用开发经验的学习者，重点解释工程方法，不追求生产级自然语言理解平台。

## 范围

### 包含

1. 单标签、单层意图体系及 `unknown` 兜底意图。
2. 标签命名、边界定义、相似意图区分和标注冲突处理。
3. 固定训练集、测试集以及数据泄漏防护。
4. 使用 Python 标准库实现可训练的文本分类器。
5. 概率阈值和第一、第二候选差距共同控制拒识。
6. 混淆矩阵、每类 Precision/Recall/F1 和宏平均指标。
7. 错误样本分析和线上样本回流原则。
8. 可重复执行的命令行 Demo 和单元测试。

### 不包含

1. 多标签、层级意图或槽位抽取。
2. 神经网络、Transformer 训练或 GPU 依赖。
3. 调用真实模型供应商的微调 API。
4. 在线学习、模型服务部署或生产流量采集。
5. 自动标注平台和人工审核 UI。

这些内容可作为后续扩展，不纳入本次实现。

## 数据设计

样本使用 JSONL，每行结构如下：

```json
{"text":"我想取消刚才下的订单","intent":"cancel_order","split":"train"}
```

字段约束：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `text` | string | 去除首尾空白后不能为空 |
| `intent` | string | 使用小写蛇形命名，不能为空 |
| `split` | string | 只能是 `train` 或 `test` |

示例数据使用订单客服场景，至少包含：

- `query_order`
- `cancel_order`
- `request_refund`
- `human_service`

`unknown` 不作为普通训练标签。它代表分类器证据不足时的系统决策，测试集中可以包含预期为 `unknown` 的域外输入。

数据校验需要发现：

- 缺失或空字段；
- 非法 `split`；
- 同一文本重复出现；
- 同一文本被标成不同意图；
- 某个训练意图没有测试样本；
- 某个测试意图没有训练样本，`unknown` 除外。

校验函数返回结构化问题列表，CLI 在存在错误时返回非零退出码。

## 分类器设计

### 特征

文本先做以下规范化：

1. 转为小写。
2. 移除空白和标点。
3. 提取字符 unigram 和 bigram。

字符 n-gram 不依赖中文分词库，适合本仓库“标准库、离线运行”的约束，同时能直观展示文本特征如何进入分类器。

### 训练

实现多项式朴素贝叶斯：

- 统计每个意图的样本数，得到类别先验；
- 统计每个意图下的特征频次；
- 使用拉普拉斯平滑处理未见特征；
- 保存词表、类别计数、特征计数和总特征数。

模型保持为 Python 数据结构，不增加二进制模型文件。CLI 每次从示例数据训练，保证 Demo 简单且结果可复现。

### 预测与拒识

预测返回：

```json
{
  "intent": "cancel_order",
  "confidence": 0.82,
  "margin": 0.70,
  "candidates": [
    {"intent": "cancel_order", "probability": 0.82},
    {"intent": "query_order", "probability": 0.12}
  ]
}
```

实现时 `margin` 等于最高候选概率减去第二候选概率；示例中的具体数字仅表达字段含义。

当满足任一条件时返回 `unknown`：

- 最高概率低于 `confidence_threshold`；
- 第一、第二候选概率差低于 `margin_threshold`；
- 规范化后没有可用特征。

原始候选仍然保留，便于解释拒识原因和分析错误。

## 评估设计

评估只使用 `split=test` 的样本，输出：

1. 总样本数和 Accuracy。
2. 按真实标签为行、预测标签为列的混淆矩阵。
3. 每个意图的 Precision、Recall 和 F1。
4. 宏平均 Precision、Recall 和 F1。
5. 预测错误明细，包括文本、期望标签、预测标签、置信度和候选项。

所有零分母情况返回 `0.0`，不抛出除零异常。指标保留足够精度供测试比较，CLI 展示时再格式化。

## 命令行设计

Demo 提供三个子命令：

```powershell
python intent_classifier_demo.py validate
python intent_classifier_demo.py evaluate
python intent_classifier_demo.py predict --text "帮我取消订单"
```

通用参数：

- `--data`：覆盖默认 JSONL 路径；
- `--confidence-threshold`：覆盖默认置信度阈值；
- `--margin-threshold`：覆盖默认候选差距阈值。

所有输出使用 UTF-8 JSON，便于学习者观察并被其他程序消费。

错误处理规则：

- 文件不存在、JSON 非法或数据校验失败：输出明确错误并返回非零退出码；
- 训练集为空：拒绝训练；
- `predict --text` 为空：由参数校验拒绝；
- 合法但无法识别的文本：正常返回 `unknown`，退出码仍为零。

## 测试策略

采用测试驱动开发，按以下行为逐步实现：

1. 合法数据通过校验，空字段、冲突标签和数据泄漏被识别。
2. 字符 n-gram 规范化结果稳定。
3. 训练后的模型能识别典型意图。
4. 空特征、低置信度或低 margin 返回 `unknown`。
5. 混淆矩阵方向固定为“真实标签行、预测标签列”。
6. Precision、Recall、F1 和宏平均计算正确。
7. CLI 的 `validate`、`evaluate` 和 `predict` 返回正确退出码和 JSON。

专题测试通过后，还需要运行仓库现有全部 Python、Node 和 Java 测试，并重新检查 Markdown 本地链接。
