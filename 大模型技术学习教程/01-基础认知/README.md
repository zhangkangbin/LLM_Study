# 阶段一：基础认知

本阶段目标是建立大模型技术的整体地图。学完后，你应该能分清大模型、机器学习、RAG、Agent、微调、多模态这些概念之间的关系，并知道一个大模型应用在 Android、后端、前端中分别应该怎么分工。

这一阶段的“基础认知”不是让你背算法名词，而是建立几个工程直觉：

- 大模型为什么不是数据库。
- 为什么同样的问题可能得到不同答案。
- 为什么训练、推理、微调、量化、蒸馏不是一回事。
- 为什么 Token、词表、上下文窗口和 Embedding 会影响成本、速度和质量。
- 为什么 Prompt、RAG、工具调用、微调解决的是不同层面的问题。
- 为什么一个能上线的大模型应用必须有后端控制、日志、评估和人工确认。

## 本阶段你会学到什么

1. 大模型和传统机器学习、深度学习是什么关系。
2. 大模型应用和普通 App / Web / 后台服务有什么区别。
3. 训练、推理、微调、量化、蒸馏这些模型生命周期概念是什么意思。
4. Token、词表、上下文窗口、Embedding、Transformer、推理参数这些词是什么意思。
5. 为什么大模型会出现幻觉和随机性，以及工程上如何降低影响。
6. 一个 Android 大模型应用通常应该采用什么架构。
7. 后续学习 API、Prompt、RAG、Agent 时应该关注什么。

## 学习建议

这一阶段不要陷入算法细节。你暂时不需要从零推导神经网络，也不需要实现训练框架。作为应用开发者，优先理解下面这条主线：

```text
用户输入 -> 业务上下文 -> 模型调用 -> 工具/知识库 -> 结果生成 -> 产品体验
```

后面的 API、Prompt、RAG、Agent、Android 接入，都是围绕这条主线展开。

## 学完后的自检问题

读完本阶段后，不要求你能推导神经网络公式，但应该能用自己的话回答：

- 模型为什么会“像知道答案”，但又可能编造事实？
- 训练、推理、微调、量化、蒸馏分别改变了什么？
- Token、词表、tokenizer 是什么关系？
- 上下文窗口为什么不是越大越好？
- Embedding 为什么能做语义搜索，但不能替代数据库查询？
- RAG 为什么能补知识，却不能保证模型一定答对？
- 推理参数为什么只能影响生成方式，不能替代可靠资料？
- Agent 为什么需要工具权限、日志和停止条件？
- Android 端为什么应该通过后端调用模型，而不是直接拿 API Key 调模型？
