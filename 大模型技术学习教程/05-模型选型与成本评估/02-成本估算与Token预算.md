# 02. 成本估算与 Token 预算

## 1. 成本为什么容易失控

大模型成本通常不是按请求固定收费，而是和 Token、工具调用、音频时长、图片处理、容器会话等因素有关。

最常见的是文本 Token 费用：

```text
输入成本 + 输出成本 = 单次模型调用成本
```

如果使用缓存输入、工具调用、Web search、File search、Realtime、音频等能力，还要额外计算对应费用。

## 2. 基础公式

如果价格单位是“每 100 万 Token”，则：

```text
输入成本 = 输入 Token / 1,000,000 * 输入单价
输出成本 = 输出 Token / 1,000,000 * 输出单价
总成本 = 输入成本 + 输出成本
```

如果有缓存输入：

```text
普通输入成本 = 非缓存输入 Token / 1,000,000 * 输入单价
缓存输入成本 = 缓存输入 Token / 1,000,000 * 缓存输入单价
输出成本 = 输出 Token / 1,000,000 * 输出单价
```

## 3. 示例

假设某模型：

```text
输入：$5 / 1M tokens
缓存输入：$0.5 / 1M tokens
输出：$30 / 1M tokens
```

一次请求：

```text
输入 10,000 tokens
其中 4,000 tokens 命中缓存
输出 2,000 tokens
```

计算：

```text
普通输入：6,000 / 1,000,000 * 5 = $0.03
缓存输入：4,000 / 1,000,000 * 0.5 = $0.002
输出：2,000 / 1,000,000 * 30 = $0.06
总计：$0.092
```

这就是本阶段 Demo 中测试的公式。

## 4. 月成本估算

月成本可以先粗略估：

```text
月成本 = 单次平均成本 * 每日请求量 * 天数
```

例如：

```text
单次 $0.01
每天 10,000 次
30 天
月成本 = $3,000
```

很多大模型应用不是贵在单次，而是贵在高频调用和长上下文。

## 5. 影响成本的关键因素

### 输入 Token

来源：

- 用户问题
- 系统 Prompt
- 历史消息
- RAG 文档片段
- 工具返回结果
- 图片或多模态内容转成的 token 表示

优化方式：

- 裁剪历史消息
- 压缩上下文
- 减少无关文档
- 使用缓存
- 做多阶段模型路由

### 输出 Token

来源：

- 模型最终回答
- 结构化 JSON
- 工具调用参数
- 推理模型的输出预算

优化方式：

- 限制输出长度
- 使用结构化输出
- 明确回答风格
- 不让模型输出无用解释

### 工具调用

某些内置工具可能按调用次数或检索内容计费。

例如：

- Web search
- File search
- Code Interpreter / Hosted Shell
- Realtime 音频

工具调用不仅有工具本身费用，还可能增加输入 Token，因为工具结果会被放回上下文。

## 6. Android 场景成本预算

### 崩溃日志分析

成本主要来自：

- 崩溃日志长度
- 最近改动上下文
- RAG 检索片段
- 输出分析报告

优化：

- 先提取关键堆栈再发送。
- 不上传完整 logcat。
- 高频自动分析用中小模型。
- 高风险问题再升级强模型。

### 语音助手

成本主要来自：

- ASR
- LLM
- TTS
- Realtime 音频

优化：

- 本地先做唤醒词和简单意图。
- 短问题用低延迟模型。
- 长任务异步处理。
- 复用上下文缓存。

### AI 代码 Review

成本主要来自：

- diff 长度
- 相关文件上下文
- 多轮工具调用
- 输出详细 Review

优化：

- 先用规则过滤无风险 diff。
- 大文件分块分析。
- 中模型初筛，强模型复核。
- 建立缓存和增量分析。

## 7. 成本监控指标

上线后至少记录：

- 每个场景的请求量
- 平均输入 Token
- 平均输出 Token
- 平均成本
- P50 / P95 延迟
- 模型分布
- 工具调用次数
- 失败率

不要只看总账单，要按业务场景拆分。

## 8. 本章小结

成本控制的核心不是一味选择便宜模型，而是：

```text
减少无效上下文
控制输出长度
按任务选择模型
高频任务用小模型
高风险任务用强模型
持续记录和评估
```
