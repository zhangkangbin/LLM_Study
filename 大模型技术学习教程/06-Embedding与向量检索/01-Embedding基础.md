# 01. Embedding 基础

## 1. Embedding 是什么

Embedding 是把文本、图片等内容转换成向量的技术。

向量可以理解为一组数字：

```text
"Android 崩溃日志" -> [0.12, -0.03, 0.87, ...]
```

模型会把语义相近的内容映射到距离更近的向量空间里。

例如：

```text
"Android 崩溃日志怎么分析"
"App Crash 如何排查"
```

这两句话字面不完全一样，但语义接近。Embedding 可以帮助系统找到它们的相似性。

## 2. Embedding 能做什么

常见用途：

- 语义搜索
- RAG 知识库问答
- 相似问题推荐
- 文档聚类
- 异常检测
- 分类
- 代码片段检索
- 崩溃问题归类

在大模型应用里，最常见的是 RAG：

```text
用户问题 -> 向量化 -> 检索相关文档 -> 交给大模型回答
```

## 3. 向量距离和相似度

向量检索的核心是比较两个向量有多像。

常见方法：

- 余弦相似度
- 欧氏距离
- 点积

学习阶段先理解余弦相似度就够了。

余弦相似度越接近 1，表示越相似；越接近 0，表示相关性越弱。

```text
query vector vs document vector -> score
```

然后按 score 排序，取 Top-K。

## 4. Embedding 和 LLM 的区别

LLM 用来生成答案。

Embedding 用来表示语义、计算相似度。

它们的职责不同：

```text
Embedding：负责找相关内容
LLM：负责理解和生成答案
```

不要让 LLM 直接阅读全部文档。应该先用 Embedding 检索出相关片段，再把片段交给 LLM。

## 5. Embeddings API 请求

真实项目中，可以调用 Embeddings API：

```json
{
  "model": "text-embedding-3-small",
  "input": [
    "Android 崩溃日志怎么分析",
    "ANR 主线程无响应怎么排查"
  ],
  "encoding_format": "float"
}
```

响应中会包含每条输入对应的向量和 usage 信息。

## 6. 维度是什么

Embedding 向量有维度，比如 1536、3072 或自定义维度。

可以粗略理解为：

```text
维度越多，表达能力可能更强，但存储和检索成本也更高。
```

真实选型时要考虑：

- 检索质量
- 存储成本
- 查询速度
- 向量数据库支持
- 业务场景是否需要高精度

## 7. Android 开发者怎么理解

你可以把向量检索理解成一种“语义版搜索引擎”。

普通关键词搜索：

```text
必须命中关键词
```

向量检索：

```text
即使命中的词不同，也能找语义相近的内容
```

例如用户问：

```text
App 卡死无响应怎么查？
```

向量检索可能找到：

```text
ANR 表示主线程长时间无响应...
```

即使用户没有说 ANR。

Embedding 的核心价值是：

```text
把文本变成可以计算相似度的向量。
```
