# 引用展示、富文本渲染与多端体验

AI 应用的前端体验不只是“显示文字”。真实产品里还要处理引用、Markdown、代码块、表格、图片、工具进度、错误恢复和多端一致性。

## RAG 引用展示

RAG 答案应该把引用作为结构化数据返回：

```json
{
  "answer": "先看 FATAL EXCEPTION。",
  "citations": [
    {
      "label": "[android-crash-guide#0]",
      "title": "Android 崩溃排查",
      "sourceUri": "app://knowledge/android/crash"
    }
  ]
}
```

前端可以把引用展示成可点击标签。点击后打开文档、知识库片段或底部弹窗。

## 引用卡片例子

Android 知识库助手可以把引用渲染成轻量卡片，而不是只在答案末尾拼一段文字：

| 字段 | 展示方式 |
| --- | --- |
| `label` | 短标签，例如 `[crash-guide#2]` |
| `title` | 卡片主标题，例如“Android 空指针排查” |
| `sourceUri` | 点击后打开知识库片段或详情页 |
| `snippet` | 可选，展示命中的 1 到 2 行原文摘要 |
| `confidence` | 可选，低置信度时提示“建议人工确认” |

一个回答可以先流式展示正文，引用事件稍后到达时再补到同一条 assistant 消息下面。引用卡片要和 `trace_id` 绑定，方便用户反馈“这条引用不对”时定位后端检索记录。

## Markdown 渲染

常见内容类型：

1. 普通段落。
2. 列表。
3. 代码块。
4. 表格。
5. 链接。
6. 图片。
7. 引用块。

渲染时要注意：

1. 不要直接把模型输出当 HTML 注入。
2. 链接要有安全策略。
3. 代码块要支持复制。
4. 表格在移动端要横向滚动。
5. 超长单词或 URL 要换行。
6. 流式期间 Markdown 可能不完整，要能容错。

## Agent 进度展示

Agent 不应该只显示“正在思考”。更好的方式是展示可理解进度：

| Agent 步骤 | 前端展示 |
| --- | --- |
| 检索知识库 | 正在查找相关资料 |
| 调用工具 | 正在创建工单 |
| 等待审批 | 等待你确认 |
| 生成总结 | 正在整理结果 |
| 完成 | 显示结果和 trace |

用户不需要看到所有内部参数，但需要知道系统正在做什么，以及能否取消。

## 错误 UI 例子

错误 UI 要告诉用户发生了什么、能不能重试、是否保留已输入内容。

| 错误码 | 用户可见文案 | UI 动作 |
| --- | --- | --- |
| `AI_RATE_LIMITED` | 当前分析请求较多，请稍后再试 | 显示倒计时或稍后重试按钮 |
| `AI_RETRIEVAL_TIMEOUT` | 暂时没能检索知识库，可以只基于日志分析 | 提供“继续普通分析” |
| `AI_PROVIDER_TIMEOUT` | 模型响应超时，已保留你的问题 | 显示重新生成 |
| `AI_NO_ANSWER` | 知识库没有找到可靠答案 | 引导补充日志或创建人工工单 |
| `USER_CANCELLED` | 已停止生成 | 保留已生成片段，允许重新生成 |

不要把后端堆栈、供应商错误原文或内部 Prompt 暴露给用户。调试信息可以挂在反馈入口的 `trace_id` 上。

## 多端体验

Web 和 Android 应该复用同一套后端事件语义：

| 事件 | 含义 |
| --- | --- |
| `message.started` | assistant 消息开始 |
| `message.delta` | 增量文本 |
| `message.completed` | 当前消息完成 |
| `message.citation` | 引用信息 |
| `tool.started` | 工具开始 |
| `tool.completed` | 工具结束 |
| `response.error` | 错误 |
| `response.cancelled` | 取消 |

前端框架可以不同，但事件协议最好统一。

## 实时语音场景

OpenAI Realtime 文档建议浏览器或移动端媒体场景优先考虑 WebRTC；服务端到服务端或服务器媒体管线可以用 WebSocket。对于普通文本聊天，SSE 或普通 HTTP 通常足够；对于语音对话、低延迟双向音频，才需要考虑 Realtime。

选择方式：

| 技术 | 适合场景 |
| --- | --- |
| 普通 HTTP | 短响应、非实时 |
| SSE | 文本流式输出 |
| WebSocket | 双向事件、服务端管线 |
| WebRTC | 浏览器/移动端实时音频 |

不要为了炫技把所有 AI 聊天都做成 WebSocket。先按交互需求选最简单的协议。
