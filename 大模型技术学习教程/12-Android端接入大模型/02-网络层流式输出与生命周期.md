# 网络层、流式输出与生命周期

Android 端接入大模型时，网络层比普通接口更复杂，因为大模型响应可能持续几秒到几十秒，期间用户可能返回、切后台、断网或取消。

## 普通响应和流式响应

| 响应方式 | 适合场景 |
| --- | --- |
| 普通 HTTP | 短文本、分类、结构化抽取 |
| SSE/流式 HTTP | 聊天、长答案、RAG 解释 |
| WebSocket | 双向事件、多步骤 Agent 进度 |
| WebRTC | 实时语音、低延迟音频会话 |

OpenAI 官方文档说明，Streaming 可以在完整输出生成前先处理模型输出；Realtime 文档建议浏览器/移动端媒体场景优先考虑 WebRTC。

对普通 Android 文本聊天，先用后端转发 SSE 或自定义流式协议就够了。

## Kotlin Repository 骨架

下面是伪代码骨架，真实项目可用 OkHttp、Retrofit 的 Streaming 能力或 Ktor Client：

```kotlin
class AiRepository(
    private val client: OkHttpClient,
    private val baseUrl: String,
    private val tokenProvider: TokenProvider
) {
    fun streamChat(message: String): Flow<ChatEvent> = callbackFlow {
        val request = Request.Builder()
            .url("$baseUrl/ai/chat/stream")
            .header("Authorization", "Bearer ${tokenProvider.token()}")
            .header("Accept", "text/event-stream")
            .post("""{"message": ${jsonEscape(message)}, "stream": true}""".toRequestBody())
            .build()

        val call = client.newCall(request)
        awaitClose { call.cancel() }
    }
}
```

重点不是具体库，而是：

1. 请求自己的后端。
2. 可以取消 call。
3. 把网络事件转换成 `ChatEvent`。
4. 不把网络细节暴露给 UI。

## 生命周期取消

ViewModel 里发起请求时，应该绑定 `viewModelScope`。页面离开或任务取消时，取消对应 Job。

```kotlin
private var currentJob: Job? = null

fun send(message: String) {
    currentJob?.cancel()
    currentJob = viewModelScope.launch {
        repository.streamChat(message).collect { event ->
            reduce(event)
        }
    }
}

fun cancel() {
    currentJob?.cancel()
    reduce(ChatEvent.UserCancelled)
}
```

Android 官方文档也强调 ViewModel 是屏幕级状态持有者，能在配置变化时保留状态，适合承载这类业务状态。

## 迟到事件

取消后仍可能收到网络层迟到事件。状态机要忽略迟到 delta：

```kotlin
if (state.status == ChatStatus.Cancelled) {
    return
}
```

这能避免用户点了取消，界面又继续追加文字。

## 弱网处理

弱网下要明确区分：

1. 超时：提示重试。
2. 断网：提示检查网络。
3. 429：提示稍后再试。
4. 401：重新登录。
5. 5xx：服务暂时不可用。
6. 用户取消：不要显示错误。

Android 端不要把后端原始错误直接展示给用户，而要映射成稳定用户文案。
