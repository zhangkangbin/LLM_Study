# 成本、延迟、限流与降级

大模型应用上线后，成本和延迟会很快变成产品问题。用户不关心你用了多强的模型，只关心回答是否快、是否准、是否稳定。

## 成本来源

常见成本包括：

1. 输入 token。
2. 输出 token。
3. Embedding。
4. 语音、图片、多模态处理。
5. 重试和失败请求。
6. 评估集运行。
7. 本地模型的机器成本。

控制成本不是简单换小模型，而是组合策略：

| 策略 | 作用 |
| --- | --- |
| 减少不必要请求 | 简单规则不走 LLM |
| 压缩上下文 | RAG 只放必要片段 |
| 控制输出长度 | 避免默认长篇回答 |
| 缓存稳定前缀 | 提高重复 Prompt 复用 |
| 分层模型路由 | 简单任务走小模型 |
| 异步批处理 | 非实时任务降低成本 |

## 延迟优化

延迟通常由几部分组成：

```mermaid
flowchart LR
    Client["客户端网络"] --> Gateway["后端网关"]
    Gateway --> Retrieve["检索/工具"]
    Retrieve --> Model["模型推理"]
    Model --> Stream["流式输出"]
    Stream --> UI["客户端渲染"]
```

优化顺序建议：

1. 先流式输出，让用户尽早看到内容。
2. 减少输出 token。
3. 减少检索和工具串行等待。
4. 并行化可并行步骤。
5. 对高频场景使用缓存。
6. 对低价值任务异步化。

## 限流与预算

至少要有三层限制：

1. 用户级：防止单用户刷爆成本。
2. 租户级：防止企业客户超预算。
3. 系统级：保护整体供应商额度和队列。

当触发限制时，不要只返回 500。应该给出明确状态：

```json
{
  "code": "AI_BUDGET_LIMITED",
  "message": "当前 AI 使用额度已达上限，请稍后再试或联系管理员。",
  "retryable": false
}
```

## 降级策略

| 故障 | 降级 |
| --- | --- |
| 大模型接口超时 | 返回缓存答案或转人工 |
| RAG 检索失败 | 普通模型回答并标明未检索 |
| TTS 失败 | 只展示文本 |
| 高级模型不可用 | 切换小模型 |
| Agent 工具失败 | 停止执行并解释失败点 |

降级不是偷懒，而是让系统在坏天气里仍然有边界。
