# 面向端侧的生成模型训练与量化

端侧模型的目标不是“把能训练的最小模型塞进手机”，而是让一个经过版本冻结、任务评估和量化复测的模型，在目标设备上满足明确的质量、延迟、内存和安全门槛。本章以 `Qwen/Qwen3-0.6B` 为可替换示例，完成工作站上的 LoRA/QLoRA、合并、GGUF 转换和 Q4_K_M 量化；它不保证 0.6B 模型一定适合你的业务或手机，最终结论必须来自固定评测集和真机测量。

核心文件：

- [Chat JSONL 校验器](./demo/mobile_llm_dataset_demo.py)
- [示例 Chat JSONL](./demo/sample_mobile_llm_chat.jsonl)

> **接口冻结说明**：本章按 2026-07-16 可查到的 Hugging Face、Qwen、PEFT、bitsandbytes 与 `ggml-org/llama.cpp` 官方接口编写。训练库和转换器仍会变化。先完成一次成功运行，再把 `pip freeze`、基座模型 commit、数据 SHA-256 和 llama.cpp commit 一起冻结到实验报告；以后复现实验按这些版本运行，不让 `main` 漂移。若当前官方 API 与旧计划或旧文章字段不同，以本章核对到的真实 API 为准。

## 1. 先决定是否值得训练

固定客服任务先做规则、Prompt 或检索基线。只有基线不能达到已经定义的门槛，并且失败可以由高质量示例修正时，才进入适配器训练。

| 决策项 | 0.5B～1B 起步时要检查什么 | 不能据此下的结论 |
| --- | --- | --- |
| 中文与固定任务基线 | 用同一批订单、摘要、安全拒绝和离线边界 Prompt 测基础模型 | “参数小，所以中文一定够用” |
| 开放权重许可 | 在具体 commit 的 model card 与 LICENSE 中核对商用、分发、衍生物要求 | 模型可下载不等于可任意分发 |
| 数据许可 | 分别核对来源、标注授权、隐私、删除与训练用途 | 基座许可不能替代数据许可 |
| Tokenizer / Chat Template | 训练、Transformers 推理和 llama.cpp 必须使用兼容的 tokenizer、角色模板与 EOS | 文本看起来相同不代表 token 序列相同 |
| 转换支持 | 在冻结的 llama.cpp commit 上确认 `convert_hf_to_gguf.py` 支持该架构 | 另一个 Qwen/Llama 版本能转，不代表当前 revision 能转 |
| 版本链 | 分别记录 base ID + commit、adapter 配置/哈希或 Hub commit，以及转换器 commit | 只记 `Qwen3-0.6B` 或 `main` 无法复现 |
| 设备预算 | 估算磁盘、RAM、KV cache，再在目标手机测峰值和长上下文 | 桌面能运行不等于手机满足门槛 |

建议先在 0.5B～1B 量级验证完整闭环，再由业务评测决定是否扩大模型。`Qwen/Qwen3-0.6B` 只是默认 `MODEL_ID`；替换模型或 revision 后，必须重新检查 model card、许可、chat template、assistant mask、目标层名称和 llama.cpp 转换支持。

粗略容量只能用于排期。权重下限约为 `参数量 × 位宽 / 8`：0.6B 的 F16 原始权重约 1.2 GB，4 bit 原始权重约 0.3 GB，实际文件还包含量化尺度、张量元数据和 tokenizer。KV cache 可按 `2 × 层数 × KV heads × head_dim × 每元素字节 × 上下文 token × batch` 估算，还要叠加运行时、计算缓冲、应用进程和系统占用。不同后端可能量化或重排 KV，所有数字都要在目标上下文长度和真实手机上复测。

本章不在手机上训练。训练还需要反向传播、优化器状态、较长时间的稳定散热和成熟的 CUDA/加速库；手机的统一内存、热降频、电池和后台生命周期都不适合作为可复现训练环境。正确边界是“工作站训练与合并，桌面转换，手机只做受控推理和测量”。

## 2. 冻结可复现环境和输入

在仓库根目录创建专用环境。下面保留“先安装当前兼容版本、成功后冻结”的流程：

```powershell
python -m venv .venv-mobile-llm
.\.venv-mobile-llm\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install 'transformers' 'datasets' 'accelerate' 'trl[peft]' 'bitsandbytes'
pip freeze | Set-Content -Encoding UTF8 training-requirements-lock.txt
```

第一次 `pip freeze` 是候选环境快照；训练和评估成功后再执行一次，并把最终 lock 放进实验归档。还要保存 Python、CUDA toolkit、NVIDIA driver、GPU、所有包版本、完整命令、seed、基座 commit 和数据 SHA-256。这个仓库不提交环境特定的 lock、`.venv-mobile-llm`、模型权重、adapter、merged 目录或 GGUF；它们进入受控制品存储。

训练前先运行本仓库校验器。`load_dataset("json", ...)` 会把单个文件映射成名为 `train` 的容器 split，文件内的 `split` 字段仍要由代码二次筛选：

```powershell
$Validator = '.\大模型技术学习教程\16-微调与模型定制\demo\mobile_llm_dataset_demo.py'
$Dataset = '.\大模型技术学习教程\16-微调与模型定制\demo\sample_mobile_llm_chat.jsonl'
python $Validator validate --data $Dataset --max-characters 4096
if ($LASTEXITCODE -ne 0) { throw 'Chat JSONL 校验失败，停止训练' }
$DatasetSha = (Get-FileHash -Algorithm SHA256 $Dataset).Hash.ToLowerInvariant()
```

这 12 行 sample 只用于 schema、split、mask、训练和转换流程 smoke test，不能证明模型质量或泛化；正式运行第 3 节命令前，先按第 4 节生成并冻结独立 `$HoldoutSuite`。

不要把 `main` 直接交给训练进程。先通过 Hub API 把可读 revision 解析成 immutable commit SHA，再把 SHA 传给所有下载操作：

```powershell
$ModelId = 'Qwen/Qwen3-0.6B'
$RequestedRevision = 'main'
$env:MODEL_ID_TO_RESOLVE = $ModelId
$env:MODEL_REVISION_TO_RESOLVE = $RequestedRevision
$BaseCommit = (python -c "import os; from huggingface_hub import HfApi; print(HfApi().model_info(os.environ['MODEL_ID_TO_RESOLVE'], revision=os.environ['MODEL_REVISION_TO_RESOLVE']).sha)").Trim()
if ($BaseCommit -notmatch '^[0-9a-f]{40}$') { throw "未得到 immutable Hugging Face commit SHA: $BaseCommit" }
$BaseCommit
```

解析 SHA 的网络响应也不是许可结论。打开该 commit 对应的 [Qwen3-0.6B model card](https://huggingface.co/Qwen/Qwen3-0.6B)，同时核对 LICENSE；换 revision 后重新核对。Hub 的 `HfApi.model_info(...).sha` 定义见 [Hugging Face Hub API](https://huggingface.co/docs/huggingface_hub/package_reference/hf_api)。

## 3. 完整 LoRA / QLoRA 训练脚本

下面保存为 `train_mobile_adapter.py`。当前 TRL 使用 `SFTConfig(eval_strategy=..., max_length=...)`，不是旧示例常见的 `evaluation_strategy` 或 `max_seq_length`；tokenizer 通过 `SFTTrainer(processing_class=...)` 传入。脚本从同一 immutable commit 独立加载 deployment tokenizer 与 training tokenizer：前者永久保持模型原始部署模板，后者才接收 TRL 返回的 `{% generation %}` 训练模板。训练器只使用 training tokenizer；adapter 保存时直接保存 PEFT 模型，再保存并重载验证 deployment tokenizer，避免 `Trainer.save_model()` 把训练专用模板带进发布制品。

`assistant_only_loss=True` 只有在 chat template 能生成 assistant token mask 时才成立。脚本先通过 TRL 官方 `get_training_chat_template()` 取得带 `{% generation %}` / `{% endgeneration %}` 标记的兼容模板，再逐条请求 `return_assistant_tokens_mask=True`；train/validation 任一样本超过实际 `SFTConfig.max_length`，或 mask 缺失、全零、长度不一致、最终 assistant EOS 的完整 token 序列未被 mask 覆盖，都会在训练前直接失败，绝不依赖 TRL 静默过滤或截断。Qwen3 官方 model card 说明 thinking 默认开启，并支持 `enable_thinking=False` 硬开关；本章固定为非思考模式，训练、评估和部署都必须保持一致。

```python
def sha256_file(path: Path) -> str:
    digest = hashlib.sha256()
    with path.open("rb") as stream:
        for chunk in iter(lambda: stream.read(1024 * 1024), b""):
            digest.update(chunk)
    return digest.hexdigest()


def read_jsonl(path: Path) -> list[dict[str, Any]]:
    if not path.is_file():
        raise FileNotFoundError(path)
    rows = []
    for line_number, line in enumerate(path.read_text(encoding="utf-8").splitlines(), 1):
        if not line.strip():
            continue
        try:
            rows.append(json.loads(line))
        except json.JSONDecodeError as error:
            raise RuntimeError(f"{path}:{line_number} 不是合法 JSON") from error
    if not rows:
        raise RuntimeError(f"JSONL 为空: {path}")
    return rows


def user_prompt(messages: list[dict[str, str]]) -> str:
    parts = [message["content"] for message in messages if message.get("role") == "user"]
    if not parts or any(not isinstance(part, str) or not part.strip() for part in parts):
        raise RuntimeError("每条记录必须包含非空 user 消息")
    return "\u241e".join(parts)


def normalize_prompt(value: str) -> str:
    normalized = unicodedata.normalize("NFKC", value).casefold()
    return "".join(character for character in normalized if character.isalnum())


def character_ngrams(value: str, width: int = 3) -> set[str]:
    if not value:
        raise ValueError("不能对空字符串计算 character n-gram")
    if width <= 0 or width > len(value):
        raise ValueError("character n-gram width 必须在 1 和字符串长度之间")
    return {value[index : index + width] for index in range(len(value) - width + 1)}


def ngram_jaccard(left: str, right: str) -> float:
    if not left or not right:
        raise ValueError("归一化 prompt 不能为空")
    width = min(3, len(left), len(right))
    left_ngrams = character_ngrams(left, width)
    right_ngrams = character_ngrams(right, width)
    return len(left_ngrams & right_ngrams) / len(left_ngrams | right_ngrams)


def assert_suite_independent(
    data_path: Path,
    suite_path: Path,
    threshold: float = SUITE_NEAR_DUPLICATE_THRESHOLD,
) -> dict[str, Any]:
    if not 0.0 < threshold < 1.0:
        raise ValueError("near-duplicate threshold 必须在 0 和 1 之间")
    training_rows = [
        row for row in read_jsonl(data_path) if row.get("split") in {"train", "validation"}
    ]
    suite_rows = read_jsonl(suite_path)
    if not training_rows:
        raise RuntimeError("train/validation 为空，无法做泄漏检查")
    suite_ids = [row.get("id") for row in suite_rows]
    if any(not isinstance(row_id, str) or not row_id for row_id in suite_ids):
        raise RuntimeError("holdout suite 每行都必须有非空 id")
    if len(suite_ids) != len(set(suite_ids)):
        raise RuntimeError("holdout suite id 重复")

    comparisons = 0
    max_similarity = 0.0
    for suite_row in suite_rows:
        suite_prompt = user_prompt(suite_row["messages"])
        suite_normalized = normalize_prompt(suite_prompt)
        if not suite_normalized:
            raise RuntimeError(f"holdout {suite_row['id']} 的 user prompt 归一化后为空")
        for training_row in training_rows:
            training_prompt = user_prompt(training_row["messages"])
            training_normalized = normalize_prompt(training_prompt)
            if not training_normalized:
                raise RuntimeError(
                    f"训练数据 {training_row['id']} 的 user prompt 归一化后为空"
                )
            if suite_prompt == training_prompt:
                raise RuntimeError(
                    f"holdout {suite_row['id']} 与 {training_row['id']} exact 重复"
                )
            if suite_normalized == training_normalized:
                raise RuntimeError(
                    f"holdout {suite_row['id']} 与 {training_row['id']} normalized 重复"
                )
            similarity = ngram_jaccard(suite_normalized, training_normalized)
            comparisons += 1
            max_similarity = max(max_similarity, similarity)
            if similarity >= threshold:
                raise RuntimeError(
                    f"holdout {suite_row['id']} 与 {training_row['id']} 疑似近重复: "
                    f"jaccard={similarity:.3f} >= {threshold:.3f}"
                )
    return {
        "path": str(suite_path.resolve()),
        "sha256": sha256_file(suite_path),
        "rows": len(suite_rows),
        "checked_splits": ["train", "validation"],
        "comparisons": comparisons,
        "near_duplicate_threshold": threshold,
        "near_duplicate_method": "character_ngram_jaccard_width=min(3,left,right)",
        "max_observed_similarity": max_similarity,
        "passed": True,
    }


def chat_template_text(tokenizer) -> str:
    if not tokenizer.chat_template:
        raise RuntimeError("tokenizer 没有 chat template")
    return (
        tokenizer.chat_template
        if isinstance(tokenizer.chat_template, str)
        else json.dumps(tokenizer.chat_template, ensure_ascii=False, sort_keys=True)
    )


def deployment_template_fingerprint(tokenizer) -> dict[str, Any]:
    template_text = chat_template_text(tokenizer)
    rendered = tokenizer.apply_chat_template(
        DEPLOYMENT_PROBE_MESSAGES,
        tokenize=False,
        add_generation_prompt=True,
        **CHAT_TEMPLATE_KWARGS,
    )
    token_ids = tokenizer.apply_chat_template(
        DEPLOYMENT_PROBE_MESSAGES,
        tokenize=True,
        add_generation_prompt=True,
        **CHAT_TEMPLATE_KWARGS,
    )
    return {
        "template_sha256": hashlib.sha256(template_text.encode("utf-8")).hexdigest(),
        "rendered_sha256": hashlib.sha256(rendered.encode("utf-8")).hexdigest(),
        "token_ids": list(token_ids),
        "token_ids_sha256": hashlib.sha256(
            json.dumps(list(token_ids), separators=(",", ":")).encode("ascii")
        ).hexdigest(),
        "template_kwargs": dict(CHAT_TEMPLATE_KWARGS),
    }


def assert_deployment_tokenizer_equivalent(expected, actual, label: str) -> dict[str, Any]:
    expected_fingerprint = deployment_template_fingerprint(expected)
    actual_fingerprint = deployment_template_fingerprint(actual)
    if actual_fingerprint != expected_fingerprint:
        raise RuntimeError(f"{label} deployment tokenizer/template/token IDs 不一致")
    return actual_fingerprint


def resolve_model_commit(model_id: str, revision: str) -> str:
    sha = HfApi().model_info(model_id, revision=revision).sha
    if sha is None or re.fullmatch(r"[0-9a-f]{40}", sha) is None:
        raise RuntimeError(f"Hub 未返回 immutable commit SHA: {sha!r}")
    if re.fullmatch(r"[0-9a-f]{40}", revision) and revision != sha:
        raise RuntimeError(f"请求 SHA {revision} 被解析为不同 commit {sha}")
    return sha


def preflight_runtime(use_qlora: bool) -> None:
    if os.environ.get("WORLD_SIZE", "1") != "1":
        raise RuntimeError("本示例只允许单进程；请用 accelerate --num_processes 1")

    if not torch.cuda.is_bf16_supported():

    if use_qlora:
        try:
            import bitsandbytes  # noqa: F401
        except Exception as error:
            raise RuntimeError("bitsandbytes/backend 预检失败") from error


def load_chat_splits(path: Path) -> tuple[Dataset, Dataset, int, str]:
    if not path.is_file():
        raise FileNotFoundError(path)
    raw = load_dataset("json", data_files=str(path), split="train")
    required = {"id", "split", "messages"}
    if not required.issubset(raw.column_names):
        raise RuntimeError(f"数据缺少字段: {sorted(required - set(raw.column_names))}")

    def add_template_kwargs(_: dict[str, Any]) -> dict[str, dict[str, bool]]:
        return {"chat_template_kwargs": dict(CHAT_TEMPLATE_KWARGS)}

    train = raw.filter(lambda row: row["split"] == "train")
    validation = raw.filter(lambda row: row["split"] == "validation")
    test_rows = len(raw.filter(lambda row: row["split"] == "test"))
    train = train.select_columns(["messages"]).map(add_template_kwargs)
    validation = validation.select_columns(["messages"]).map(add_template_kwargs)
    expected_columns = {"messages", "chat_template_kwargs"}
    if set(train.column_names) != expected_columns or set(validation.column_names) != expected_columns:
        raise RuntimeError("送入 SFTTrainer 的数据列超出 messages/chat_template_kwargs")
    if len(train) == 0 or len(validation) == 0:
        raise RuntimeError("train 和 validation 都必须非空")
    return train, validation, test_rows, sha256_file(path)


def configure_tokenizer(tokenizer, label: str):
    if not tokenizer.chat_template:
        raise RuntimeError(f"{label} tokenizer 没有 chat template")
    if tokenizer.eos_token_id is None:
        raise RuntimeError(f"{label} tokenizer 没有 EOS token")
    if tokenizer.pad_token_id is None:
        tokenizer.pad_token = tokenizer.eos_token
    tokenizer.padding_side = "right"
    return tokenizer


def prepare_tokenizers(model_id: str, commit: str):
    deployment_tokenizer = configure_tokenizer(
        AutoTokenizer.from_pretrained(model_id, revision=commit), "deployment"
    )
    training_tokenizer = configure_tokenizer(
        AutoTokenizer.from_pretrained(model_id, revision=commit), "training"
    )
    training_template = get_training_chat_template(
        processing_class=training_tokenizer
    )
    if training_template is not None:
        training_tokenizer.chat_template = training_template
    if not training_tokenizer.chat_template:
        raise RuntimeError("TRL 未提供可生成 assistant mask 的 training template")
    return deployment_tokenizer, training_tokenizer


def find_last_subsequence(sequence: list[int], subsequence: list[int]) -> int:
    for start in range(len(sequence) - len(subsequence), -1, -1):
        if sequence[start : start + len(subsequence)] == subsequence:
            return start
    return -1


def assert_assistant_masks(
    tokenizer, datasets: dict[str, Dataset], max_length: int
) -> dict[str, dict[str, int | bool]]:
    if max_length <= 0:
        raise ValueError("max_length 必须为正整数")
    eos_ids = tokenizer.encode(tokenizer.eos_token, add_special_tokens=False)
    if not eos_ids:
        raise RuntimeError("tokenizer EOS 无法编码为 token 序列")
    summary: dict[str, dict[str, int | bool]] = {}
    for split_name, dataset in datasets.items():
        max_tokens = 0
        for index, row in enumerate(dataset):
            if not row["messages"] or row["messages"][-1].get("role") != "assistant":
                raise RuntimeError(f"{split_name}[{index}] 最后一轮必须是 assistant")
            kwargs = row["chat_template_kwargs"]
            encoded = tokenizer.apply_chat_template(
                row["messages"],
                tokenize=True,
                add_generation_prompt=False,
                return_dict=True,
                return_assistant_tokens_mask=True,
                **kwargs,
            )
            input_ids = encoded.get("input_ids")
            assistant_masks = encoded.get("assistant_masks")
            if input_ids is None or assistant_masks is None:
                raise RuntimeError(f"{split_name}[{index}] 未产生 assistant mask")
            if len(input_ids) != len(assistant_masks) or 1 not in assistant_masks:
                raise RuntimeError(f"{split_name}[{index}] assistant mask 无效")
            if len(input_ids) > max_length:
                raise RuntimeError(
                    f"{split_name}[{index}] 有 {len(input_ids)} tokens，超过训练 "
                    f"max_length={max_length}；请修复样本或显式调整参数，禁止静默截断"
                )
            max_tokens = max(max_tokens, len(input_ids))
            rendered = tokenizer.apply_chat_template(
                row["messages"],
                tokenize=False,
                add_generation_prompt=False,
                **kwargs,
            )
            if not rendered.rstrip().endswith(tokenizer.eos_token):
                raise RuntimeError(
                    f"{split_name}[{index}] 模板末尾不是 tokenizer EOS，请先对齐模板/EOS"
                )
            eos_start = find_last_subsequence(input_ids, eos_ids)
            if eos_start < 0:
                raise RuntimeError(f"{split_name}[{index}] token 序列中缺少最终 EOS")
            eos_end = eos_start + len(eos_ids)
            if assistant_masks[eos_start:eos_end] != [1] * len(eos_ids):
                raise RuntimeError(
                    f"{split_name}[{index}] 最终 assistant EOS 的完整 token 序列未被 mask=1 覆盖"
                )
            trailing = tokenizer.decode(
                input_ids[eos_end:], skip_special_tokens=False
            )
            if trailing.strip():
                raise RuntimeError(
                    f"{split_name}[{index}] 最终 EOS 后仍有非空白 token"
                )
        summary[split_name] = {
            "rows": len(dataset),
            "max_tokens": max_tokens,
            "max_length": max_length,
            "eos_token_count": len(eos_ids),
            "final_assistant_eos_masked": True,
        }
    return summary


def load_model(args: argparse.Namespace, commit: str):
    model_kwargs: dict[str, Any] = {
        "revision": commit,
        "dtype": torch.bfloat16,
    }
    if args.use_qlora:
        model_kwargs["quantization_config"] = BitsAndBytesConfig(
            load_in_4bit=True,
            bnb_4bit_quant_type="nf4",
            bnb_4bit_compute_dtype=torch.bfloat16,
        )
    model = AutoModelForCausalLM.from_pretrained(args.model_id, **model_kwargs)
    if args.use_qlora:
        model = prepare_model_for_kbit_training(model)
    model.config.use_cache = False
    return model


def discover_linear_modules(model, use_qlora: bool) -> list[tuple[str, str, str]]:
    linear_types: tuple[type, ...] = (torch.nn.Linear,)
    if use_qlora:
        from bitsandbytes.nn import Linear4bit

        linear_types = linear_types + (Linear4bit,)
    found = []
    for full_name, module in model.named_modules():
        if full_name and isinstance(module, linear_types):
            leaf_name = full_name.rsplit(".", 1)[-1]
            found.append((full_name, leaf_name, module.__class__.__name__))
    if not found:
        raise RuntimeError("没有发现 Linear/Linear4bit 模块")
    for full_name, leaf_name, class_name in found:
        print(f"{class_name}\t{leaf_name}\t{full_name}")
    return found


def validate_targets(
    requested: list[str], found: list[tuple[str, str, str]]
) -> list[str]:
    targets = list(dict.fromkeys(item.strip() for item in requested if item.strip()))
    if not targets:
        raise RuntimeError("先运行 --inspect-target-modules，再显式传 --target-modules")
    if any("." in item for item in targets):
        raise RuntimeError("本示例要求传上一步打印的 leaf name，而不是猜测完整路径")
    available = {leaf_name for _, leaf_name, _ in found}
    missing = sorted(set(targets) - available)
    if missing:
        raise RuntimeError(f"target_modules 不存在: {missing}; available={sorted(available)}")
    return targets

def json_safe(value: Any) -> Any:
    if value is None or isinstance(value, (str, int, float, bool)):
        return value
    if isinstance(value, Path):
        return str(value)
    if isinstance(value, dict):
        return {
            str(key): "[redacted]"
            if str(key).lower()
            in {"hub_token", "api_key", "secret", "password", "access_token"}
            else json_safe(item)
            for key, item in value.items()
        }
    if isinstance(value, (list, tuple)):
        return [json_safe(item) for item in value]
    if hasattr(value, "item"):
        return value.item()
    return str(value)
```

这个脚本明确假设“一张可见的、支持 bf16 的 CUDA GPU”。QLoRA 分支只在 `--use-qlora` 时创建 `BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4", bnb_4bit_compute_dtype=torch.bfloat16)`，并调用 `prepare_model_for_kbit_training()`。预检失败就停止，不偷偷切换 CPU、fp16 或其他量化格式。

`set_seed(args.seed, deterministic=...)` 在任何模型构造前调用，并在 `SFTTrainer` 创建、PEFT 注入和 LoRA 随机初始化前再次调用；`SFTConfig.seed/data_seed/full_determinism` 保持一致。示例命令开启 `--full-determinism`，可能显著变慢并在不支持确定性实现的算子处失败；即使如此，跨 GPU、驱动和库版本仍不承诺逐位一致，所以报告同时保存 deterministic algorithms、cuDNN、CUBLAS、软件和硬件实际状态。若为了性能不传该开关，报告会明确记录 GPU 算子可能非确定。

不要给训练加载写 `device_map="auto"`。Transformers 的 [bitsandbytes 文档](https://huggingface.co/docs/transformers/quantization/bitsandbytes)明确说明它只应用于推理；本脚本使用单进程，让 Trainer/Accelerate 管理设备。命令可以直接由 Python 启动，也可以显式使用单进程 Accelerate：

## 4. 训练前基线和固定 Prompt Suite

本节虽然排在训练脚本之后，实际执行顺序却位于第 3 节的正式训练命令之前：先冻结 suite，用下面的 exclusive-create 评测函数写出 pinned base baseline 及 SHA-256，确认 baseline 文件不可覆盖，再开始训练。validation loss 只能用于选择学习率、epoch、target modules、checkpoint 和业务阈值，不能证明泛化质量。先只用 train/validation 完成选择并冻结配置，再把数据内 `test` split 和独立 holdout 各运行一次作为最终门禁；看过结果后不得继续调参，否则它们立即降级为开发集，必须换一个新版本 holdout。仓库的 12 行 sample（包括仅 2 行 test）只够验证流程能否跑通，不能支持质量或泛化结论；真实项目要预先注册更大、版本化且有统计意义的集合。

训练脚本和评测函数都会把 holdout 的 user 消息同 train/validation 做原文、NFKC/casefold/去符号归一化、字符 n-gram Jaccard 三层检查；归一化为空立即失败，短文本按两侧最短长度把 n 从 3 降到 1 或 2，因此不会拿空集合或不存在的 3-gram 伪造零相似度。任何 exact、normalized 或阈值以上近重复都 fail-fast，并把 suite SHA-256、阈值、算法和最大相似度写入报告。这个轻量门禁不能证明“语义绝不相似”，所以仍需人工审查题意与事实来源。

下面是 Transformers 侧的核心推理与记录函数。base、adapter 和 merged 都必须通过 deployment tokenizer 多轮指纹门禁，把 `context_limit` 固定并记录为 2048，使用相同 messages、非思考模板、seed、采样参数和 `max_new_tokens=128`；prompt 本身或 prompt 加生成预算超过 2048 都会直接失败。输出用 exclusive create，已有文件即失败，写后变为只读并输出 SHA-256。自动字符串检查只是烟雾测试，任务正确、安全拒绝、格式（含多轮约束）和延迟仍需盲审或可靠业务判定器填写。

```python
def evaluate_suite(
    model,
    tokenizer,
    reference_deployment_tokenizer,
    data_path: Path,
    suite_path: Path,
    output_path: Path,
    variant: str,
    base_model_id: str,
    base_commit: str,
    seed: int = 20260715,
) -> str:
    if output_path.exists():
        raise FileExistsError(f"评测输出已存在，禁止覆盖: {output_path}")
    if not output_path.parent.is_dir():
        raise FileNotFoundError(output_path.parent)
    leakage = assert_suite_independent(data_path, suite_path)
    template_fingerprint = assert_deployment_tokenizer_equivalent(
        reference_deployment_tokenizer, tokenizer, variant
    )
    suite_sha256 = leakage["sha256"]
    model.eval()
    records = []
    for case in read_jsonl(suite_path):
        set_seed(seed)
        inputs = tokenizer.apply_chat_template(
            case["messages"],
            tokenize=True,
            add_generation_prompt=True,
            return_dict=True,
            return_tensors="pt",
            **CHAT_TEMPLATE_KWARGS,
        ).to(model.device)
        prompt_tokens = int(inputs["input_ids"].shape[1])
        if prompt_tokens > CONTEXT_LIMIT:
            raise RuntimeError(
                f"{case['id']} prompt_tokens={prompt_tokens} 超过 "
                f"context_limit={CONTEXT_LIMIT}"
            )
        if prompt_tokens + DECODE["max_new_tokens"] > CONTEXT_LIMIT:
            raise RuntimeError(
                f"{case['id']} 的 prompt 与生成预算合计 "
                f"{prompt_tokens + DECODE['max_new_tokens']}，超过 "
                f"context_limit={CONTEXT_LIMIT}"
            )
        if model.device.type == "cuda":
            torch.cuda.synchronize()
        started = time.perf_counter()
        with torch.inference_mode():
            generated = model.generate(**inputs, **DECODE)
        if model.device.type == "cuda":
            torch.cuda.synchronize()
        elapsed = time.perf_counter() - started
        new_ids = generated[0, inputs["input_ids"].shape[1] :]
        output = tokenizer.decode(new_ids, skip_special_tokens=True).strip()
        checks = case["checks"]
        auto_checks = {
            "nonempty": bool(output),
            "contains_required": any(
                text in output for text in checks.get("must_contain_any", [])
            )
            if checks.get("must_contain_any")
            else True,
            "contains_all_required": all(
                text in output for text in checks.get("must_contain_all", [])
            ),
            "excludes_forbidden": all(
                text not in output for text in checks.get("must_not_contain_any", [])
            ),
            "plain_text": ("`" * 3) not in output if checks.get("plain_text") else True,
        }
        records.append(
            {
                "id": case["id"],
                "variant": variant,
                "output": output,
                "seed": seed,
                "enable_thinking": False,
                "template_kwargs": dict(CHAT_TEMPLATE_KWARGS),
                "template_sha256": template_fingerprint["template_sha256"],
                "template_probe_token_ids_sha256": template_fingerprint[
                    "token_ids_sha256"
                ],
                "base_model_id": base_model_id,
                "base_commit": base_commit,
                "suite_sha256": suite_sha256,
                "prompt_tokens": prompt_tokens,
                "output_tokens": int(new_ids.shape[0]),
                "latency_ms": elapsed * 1000,
                "tokens_per_second": float(new_ids.shape[0]) / elapsed,
                "context_limit": CONTEXT_LIMIT,
                "decode": DECODE,
                "auto_checks": auto_checks,
                "manual_review": {
                    "task_correct": None,
                    "refusal_correct": None,
                    "format_correct": None,
                    "notes": None,
                },
            }
        )
    with output_path.open("x", encoding="utf-8", newline="\n") as stream:
        for record in records:
            stream.write(json.dumps(record, ensure_ascii=False) + "\n")
    result_sha256 = sha256_file(output_path)
    output_path.chmod(0o444)
    print(f"result={output_path.resolve()} sha256={result_sha256}")
    return result_sha256
```

至少形成以下对照，任何一阶段退化都不能被后一阶段的平均分掩盖：

| 变体 | 用途 | 必查结果 |
| --- | --- | --- |
| pinned base | 训练前基线 | nonempty、任务正确、安全拒绝、格式、延迟 |
| base + adapter | 证明适配器本身有效 | 与 base 比质量增益和新回归 |
| merged | 证明合并没有改变行为 | 与 adapter 逐例对照 |
| F16 GGUF | 隔离格式/运行时差异 | 与 merged 对照模板、EOS 和输出 |
| Q4_K_M GGUF | 衡量量化损失 | 与 F16 GGUF 对照质量、速度、内存 |

## 5. 从非 4 bit 基座合并 adapter

不要在 bitsandbytes 4 bit 基座上直接合并并把结果当作发布模型。另起一个有足够 RAM 和磁盘的进程，从相同 immutable commit 重新加载非 4 bit base，再加载 adapter。下面脚本从环境变量接收真实路径，缺值就停止：

```python
import json
import os
import re
from pathlib import Path

from peft import PeftConfig, PeftModel
from transformers import AutoModelForCausalLM, AutoTokenizer

from train_mobile_adapter import assert_deployment_tokenizer_equivalent


MODEL_ID = os.environ.get("MODEL_ID", "Qwen/Qwen3-0.6B")
BASE_COMMIT = os.environ.get("BASE_COMMIT", "")
ADAPTER_VALUE = os.environ.get("ADAPTER_DIR", "")
MERGED_VALUE = os.environ.get("MERGED_DIR", "")

if re.fullmatch(r"[0-9a-f]{40}", BASE_COMMIT) is None:
    raise RuntimeError("BASE_COMMIT 必须是 40 位 immutable SHA")
if not ADAPTER_VALUE or not MERGED_VALUE:
    raise RuntimeError("ADAPTER_DIR 和 MERGED_DIR 都必须设置")
ADAPTER_DIR = Path(ADAPTER_VALUE)
MERGED_DIR = Path(MERGED_VALUE)
if not ADAPTER_DIR.is_dir():
    raise RuntimeError("ADAPTER_DIR 不存在")
if MERGED_DIR.exists():
    raise RuntimeError("MERGED_DIR 必须不存在，禁止覆盖或复用")

report_path = ADAPTER_DIR / "training_report.json"
if not report_path.is_file():
    raise RuntimeError("adapter 缺少 training_report.json")
training_report = json.loads(report_path.read_text(encoding="utf-8"))
base_report = training_report.get("base", {})
if base_report.get("model_id") != MODEL_ID or base_report.get("commit") != BASE_COMMIT:
    raise RuntimeError("training_report 的 model_id/commit 与合并输入不一致")
adapter_config = PeftConfig.from_pretrained(ADAPTER_DIR)
if (
    adapter_config.base_model_name_or_path != MODEL_ID
    or adapter_config.revision != BASE_COMMIT
):
    raise RuntimeError("adapter_config.json 的 base model/revision 与合并输入不一致")
deployment_tokenizer = AutoTokenizer.from_pretrained(MODEL_ID, revision=BASE_COMMIT)
adapter_tokenizer = AutoTokenizer.from_pretrained(ADAPTER_DIR)
adapter_fingerprint = assert_deployment_tokenizer_equivalent(
    deployment_tokenizer, adapter_tokenizer, "adapter"
)

base = AutoModelForCausalLM.from_pretrained(
    MODEL_ID,
    revision=BASE_COMMIT,
    dtype="auto",
    low_cpu_mem_usage=True,
)
model = PeftModel.from_pretrained(base, ADAPTER_DIR)
merged = model.merge_and_unload(safe_merge=True)
merged.save_pretrained(MERGED_DIR, safe_serialization=True, max_shard_size="2GB")
deployment_tokenizer.save_pretrained(MERGED_DIR)
merged_tokenizer = AutoTokenizer.from_pretrained(MERGED_DIR)
merged_fingerprint = assert_deployment_tokenizer_equivalent(
    deployment_tokenizer, merged_tokenizer, "merged"
)
gate_path = MERGED_DIR / "deployment_tokenizer_gate.json"
with gate_path.open("x", encoding="utf-8") as stream:
    json.dump(
        {"adapter": adapter_fingerprint, "merged": merged_fingerprint},
        stream,
        ensure_ascii=False,
        indent=2,
        sort_keys=True,
    )
```

运行前设置：

```powershell
$env:MODEL_ID = $ModelId
$env:BASE_COMMIT = $BaseCommit
$env:ADAPTER_DIR = $AdapterDir
$env:MERGED_DIR = 'C:\models\mobile-llm-merged'
python .\merge_mobile_adapter.py
```

脚本先交叉核对 `training_report.json` 与 PEFT `adapter_config.json` 的 model ID/full commit；`base_model_name_or_path` 和 `revision` 是当前官方 `PeftConfig`/`LoraConfig` 字段，不手改未知 JSON 键。base、adapter、merged 推理都使用同一 deployment template + `enable_thinking=false`；adapter 与 merged 保存后分别重载，并用多轮 rendered template、完整 token IDs 和 template hash fail-fast 对照。`merged = model.merge_and_unload(...)` 的返回值必须接住；合并后模型失去 PEFT 的切换/卸载能力。合并期间内存里同时可能存在 base、adapter、合并张量，磁盘也同时保留 base cache、adapter 和 merged shards；先实测峰值并预留余量。官方语义见 [PEFT config](https://huggingface.co/docs/peft/package_reference/config)、[checkpoint/merge 文档](https://huggingface.co/docs/peft/developer_guides/checkpoint)和 [`PeftModel`](https://huggingface.co/docs/peft/package_reference/peft_model)。

## 6. 固定 llama.cpp、转换 GGUF 并量化

只使用官方 [`ggml-org/llama.cpp`](https://github.com/ggml-org/llama.cpp)（原作者 `ggerganov/llama.cpp` 的官方迁移/重定向）。`LLAMA_CPP_COMMIT` 必须由实验清单预先给出 40 位 SHA，不能在运行时把 `master` 解析成“看起来已冻结”的版本。本章示例固定为 2026-07-16 从官方 `master` 核验的 `505b1ed15ca80e2a19f12ff4ac365e40fb374053`；更新它必须重新验证转换支持、构建和评测。每次实验使用不存在的新 source dir 和新 build dir；旧目录即使看起来正常也 fail-fast。

PowerShell 示例严格校验官方 HTTPS/SSH origin、pinned HEAD、tracked+untracked clean，并用仓库外的全新 Ninja build 目录，避免复用旧 CMake cache 或二进制：

```powershell
    $ToolHashes[$Name] = (Get-FileHash -Algorithm SHA256 $ToolPaths[$Name]).Hash.ToLowerInvariant()
```

GGUF 内嵌 chat template 不等于运行时一定采用正确模式。Qwen3 的训练和 Transformers 评估固定 `enable_thinking=false`，llama.cpp 对照也要把同一 kwargs 交给模板，并检查输出没有 `<think>`。当前官方 CLI 的显式参数是 `--chat-template-kwargs`，对应环境变量是 `LLAMA_ARG_CHAT_TEMPLATE_KWARGS`。Windows PowerShell 5.1 与 7 的原生 argv 引号规则不同，因此 Windows 示例使用官方环境变量，并在启动前让 Python 真正解析一次该环境变量；这样不会把只在某一版本成立的 `\"` 转义写进命令：

```powershell
$env:LLAMA_ARG_CHAT_TEMPLATE_KWARGS = '{"enable_thinking":false}'
python -c "import json, os; assert json.loads(os.environ['LLAMA_ARG_CHAT_TEMPLATE_KWARGS']) == {'enable_thinking': False}"
if ($LASTEXITCODE -ne 0) { throw 'chat template kwargs 不是预期 JSON' }
& $Cli -m $Q4Gguf -c 2048 -n 128 --temp 0.7 --top-p 0.8 --top-k 20 --min-p 0.0 --seed 20260715 -cnv -st -p '故障记录：屏幕出现裂纹。只回答硬件或软件。'

$SourceStatus = @(git -C $LlamaRepo status --porcelain=v1 --untracked-files=all)
if ($LASTEXITCODE -ne 0) { throw '推理后读取 source tree 状态失败' }
if ($SourceStatus.Count -ne 0) { throw "推理后 source tree 不干净: $SourceStatus" }
```

Linux 的 Bash 不需要 Windows 原生参数转义，使用标准单引号即可；完整对照参数与 PowerShell 相同：

```bash

"$LLAMA_BUILD/bin/llama-cli" -m /models/mobile-llm-q4_k_m.gguf -c 2048 -n 128 --temp 0.7 --top-p 0.8 --top-k 20 --min-p 0.0 --seed 20260715 --chat-template-kwargs '{"enable_thinking":false}' -cnv -st -p '故障记录：屏幕出现裂纹。只回答硬件或软件。'

```

对 holdout 每行先把 `-m` 换成 F16 跑完整 suite，再只替换模型路径跑 Q4_K_M；base、adapter、merged、F16 和 Q4 的逐例报告与 manifest 都记录同一 suite hash、deployment template hash/kwargs、seed 和 `context_limit=2048`。转换与 GGUF 推理后再次检查 source tree clean。若 runtime 不接受 kwargs、模板未硬关闭 thinking、仍输出 thinking block，或 F16 已偏离 merged，就直接失败；不能靠删除 `<think>` 文本伪装一致。官方转换/量化顺序见 pinned commit 的 [llama.cpp quantize 文档](https://github.com/ggml-org/llama.cpp/blob/505b1ed15ca80e2a19f12ff4ac365e40fb374053/tools/quantize/README.md)，构建与 chat template 行为见[官方 build](https://github.com/ggml-org/llama.cpp/blob/505b1ed15ca80e2a19f12ff4ac365e40fb374053/docs/build.md)和 [CLI](https://github.com/ggml-org/llama.cpp/blob/505b1ed15ca80e2a19f12ff4ac365e40fb374053/tools/cli/README.md)。

Q4_K_M 通常显著减小权重和带宽，但质量、速度与内存不是单调关系：设备指令集、GPU offload、KV cache、上下文和 prompt 长度都会改变结果。保留 F16 是为了把“合并/转换问题”和“量化损失”分开；发布只在 Q4 通过同一套任务、安全和真机门槛后进行。

## 7. 制品 manifest

每次可发布实验至少记录以下信息；manifest 和报告可以进受控制品库，权重本身不要提交 Git。

| 类别 | 必填字段 |
| --- | --- |
| base | Hugging Face model ID、immutable commit、model card / LICENSE 复核日期 |
| data | 数据路径或版本、SHA-256、许可/隐私审批、train/validation/test 计数 |
| adapter | adapter 文件逐文件 SHA-256、`adapter_config.json`、base model ID/full revision、LoRA 参数、target modules、是否 QLoRA |
| training | 完整命令、两次 seed 边界、deterministic/cuDNN/CUBLAS 实际状态、Python/CUDA/driver/GPU、package lock、train/eval metrics |
| chat | deployment/training template SHA-256、多轮 rendered/token IDs 指纹、`enable_thinking=false`、EOS/pad、训练 `max_length`、assistant mask/EOS 预检 |
| merge | 非 4 bit base commit、PEFT/Transformers 版本、merge 命令、merged 文件 hash |
| llama.cpp | allowlist 后 origin、pinned HEAD、source clean 结果、全新 source/build dir、CMake 完整 argv/generator/cache hash、converter/quantizer/CLI（使用 server 时也含 server）SHA-256 |
| GGUF | F16 与 Q4 文件 SHA-256、bytes、quant type、context、内嵌 chat template 核验 |
| evaluation | 每行 seed/thinking/template kwargs+hash/base commit/suite hash、`context_limit=2048`、解码参数、只读结果 SHA-256、base/adapter/merged/F16/Q4 逐例与盲审结论 |
| device | 手机型号、OS、runtime commit、线程/offload、峰值 RAM、首 token/总延迟、tokens/s、温升 |

adapter 自己还要记录它依赖的 base commit；否则同名 base 的新 revision 可能在加载时产生难以诊断的错误。manifest 中不要保存 Hugging Face token、代理密码、云密钥、完整环境变量或含用户隐私的原始 Prompt。

## 8. 常见失败与定位顺序

| 症状 | 优先检查 | 处理边界 |
| --- | --- | --- |
| CUDA OOM | max length、batch、梯度累计、checkpoint、目标层、QLoRA 是否真正启用 | 降低明确参数并重跑完整评测，不静默截断数据 |
| assistant mask 缺失/全零 | TRL 版本、训练模板、generation 标记、逐行 kwargs | fail-fast；不能关闭 `assistant_only_loss` 冒充同一实验 |
| target module 不匹配 | 当前 commit 的实际 `Linear/Linear4bit` 输出 | 重新发现并显式设置，不跨架构复制 |
| bitsandbytes/backend 失败 | 官方支持矩阵、CUDA/driver、GPU、wheel 与包版本 | 修环境后重跑预检，不自动改 fp16/CPU |
| converter 不支持 | 冻结 llama.cpp commit、`config.json` 架构、supported models | 升级到经审核的新 commit，并重新记录/复测 |
| 输出乱码或角色泄漏 | tokenizer、GGUF chat template、EOS/pad、UTF-8、运行时模板 | 先比较 merged 与 F16 GGUF，定位转换还是运行时 |
| thinking 模式不一致 | 每行 kwargs、Transformers 推理 kwargs、llama.cpp template kwargs | 任何阶段不一致都停止，不能后处理掩盖 |
| Q4 质量下降 | merged → F16 → Q4 的逐例差异 | 改用更高精度或重新评估量化方案 |
| 手机变慢/内存高 | context、KV cache、线程、GPU offload、热降频 | 以长时间真机结果为准，不引用桌面估算 |

## 9. 完成门禁

只有以下条件全部成立，才算完成一次“面向端侧”的训练与量化，而不是只得到一个文件：

1. 校验器退出 `0`；数据与 holdout SHA-256、许可、拆分用途和三层泄漏检查已记录；12 行 sample 未被当成质量证据。
2. base revision 已解析为 40 位 immutable commit；model card/LICENSE 和转换支持按该 revision 复核。
3. 真实 Linear/Linear4bit 已打印，target modules 由人工显式选择且脚本验证存在。
4. train/validation 每条样本都产生非空 assistant mask；training tokenizer 未进入发布制品，base/adapter/merged 的 deployment 多轮 template/token IDs 指纹一致。
5. 模型构造前和 PEFT 包装前 seed 都已设置；deterministic 实际状态、完整命令、lock、Python/CUDA/driver/GPU、metrics 和 adapter hashes 已写入报告。
6. 只用 validation 完成选择并冻结；test/holdout 只在最终门禁运行一次，base、adapter、merged、F16、Q4 完成任务正确、安全拒绝、格式、多轮一致性和延迟对照，结果不可覆盖且有 SHA-256。
7. merge 校验 training report 与官方 PEFT base revision 字段，从相同 commit 的非 4 bit base 重载，`merge_and_unload()` 返回值已保存并复测。
8. llama.cpp origin/HEAD/source clean 已核验，每个 commit 使用全新 build；CMake cache 与 converter/quantizer/CLI hashes、转换和量化命令已归档，F16/Q4 的 SHA-256 与 bytes 已记录。
9. 目标手机在预先定义的 context、峰值 RAM、延迟、tokens/s、温升和质量阈值下通过；未通过就回到选型，而不是宣称 0.6B “天然适合手机”。
10. Git 中没有 `.venv`、environment lock、base/adapter/merged 权重或 GGUF。

### 本章小结

端侧生成模型的核心不是某个 LoRA 参数或某种 4 bit 格式，而是一条可追溯的证据链：固定 base 与数据，验证 assistant mask，显式选择目标层，保存 adapter 和环境报告，使用非量化基座合并，再在冻结的 llama.cpp 上转换、量化并逐阶段复测。最后只有真机质量、内存和延迟门槛能决定模型是否可以发布。
