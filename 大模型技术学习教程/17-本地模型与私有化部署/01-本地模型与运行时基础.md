# 本地模型与运行时基础

本地模型是指模型权重和推理运行时由你自己管理，运行在本机、公司服务器、私有云或边缘设备上。它常见于隐私要求高、网络隔离、成本可控、离线可用或需要定制运行环境的场景。

## 常见运行方式

| 方式 | 适合场景 |
| --- | --- |
| 桌面本地运行 | 学习、原型、离线助手 |
| 单机服务 | 内部工具、小并发 |
| GPU 推理服务 | 企业知识库、高并发 |
| Kubernetes 部署 | 多租户、弹性伸缩 |
| 边缘设备 | 低延迟、离线、现场设备 |

## 运行时关注点

1. 模型格式和量化。
2. 显存/内存占用。
3. 上下文长度。
4. 并发和吞吐。
5. 流式输出。
6. 监控和日志。
7. 授权和许可证。

不要只看“能不能跑起来”。生产环境要看它能否稳定服务真实流量。

## 粗略显存估算

一个非常粗略的估算：

```text
参数量(十亿) * 量化位数 / 8 = 权重占用 GB
```

例如 7B 模型使用 4-bit 量化，权重大约是：

```text
7 * 4 / 8 = 3.5 GB
```

实际还要加上 KV cache、运行时开销、并发、上下文长度和系统余量。

## 本地模型不等于安全

本地部署可以减少数据出边界，但不自动解决：

1. Prompt 注入。
2. 越权工具调用。
3. 日志泄露。
4. 模型输出不可信。
5. 训练数据或模型许可证问题。
6. 内部用户滥用。

安全边界仍然要做在网关、权限和审计层。
