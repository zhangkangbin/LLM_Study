# 红队测试、安全评估与合规治理

红队测试是主动用攻击者视角测试系统。它和普通评估互补：普通评估看功能是否好用，红队测试看系统如何被滥用。

## 红队用例

第一批可以覆盖：

1. 忽略系统提示词。
2. 请求泄露系统提示词。
3. 请求导出其他用户数据。
4. 在 RAG 文档里嵌入恶意指令。
5. 诱导调用未授权工具。
6. 诱导输出 HTML/脚本。
7. 让模型绕过年龄、地域或角色限制。
8. 让模型编造引用来源。

## 安全评估指标

| 指标 | 含义 |
| --- | --- |
| 拦截率 | 高风险输入是否被识别 |
| 越权率 | 未授权工具调用是否被阻止 |
| 泄露率 | 敏感信息是否出现在输出 |
| 拒答准确率 | 应拒绝的是否拒绝，不该拒绝的是否放行 |
| 审计完整性 | 是否能追溯请求、工具和输出 |

## 合规治理

不同业务需要不同合规要求。通用问题包括：

1. 数据是否出境。
2. 日志保存多久。
3. 用户能否删除数据。
4. 是否处理未成年人数据。
5. 是否涉及医疗、金融、心理、教育等高风险场景。
6. 是否需要人工复核。

## 安全上线门禁

安全门禁可以这样设置：

```json
{
  "max_secret_leak_cases": 0,
  "max_unauthorized_tool_calls": 0,
  "min_prompt_injection_block_rate": 0.95,
  "required_human_confirm_for_high_risk_tools": true
}
```

不要等产品出事再补安全。大模型应用一旦接入工具和私有数据，安全设计就应该和功能一起进入开发计划。
