# 里程碑拆解与实现顺序

综合项目要按可交付里程碑推进。每个里程碑都能运行、能演示、能测试。

## M1：MVP

目标：

1. Android 文本聊天界面。
2. 后端 `/api/chat`。
3. 固定 Prompt。
4. 流式输出。
5. 基础日志。

验收：

1. 能问一个问题并看到流式回答。
2. 断网和取消有状态。
3. 后端记录 requestId、模型、token、延迟。

## M2：知识库增强

目标：

1. 文档导入。
2. 清洗、切分、Embedding。
3. 向量检索。
4. 回答带引用。
5. 第一版评估集。

验收：

1. 10 条知识库问题命中正确文档。
2. 回答显示引用。
3. 知识库无答案时能拒答。

## M3：多模态体验

目标：

1. 语音输入。
2. 图片/截图提问。
3. TTS 播报。
4. Android 状态机完善。

验收：

1. 权限拒绝有提示。
2. 录音取消不残留任务。
3. 图片上传失败可重试。

## M4：上线准备

目标：

1. 完整评估集。
2. 安全红队用例。
3. 监控告警。
4. 灰度和回滚。
5. 发布文档。

验收：

1. 质量评估通过。
2. 高危安全用例通过。
3. 成本和延迟有阈值。
4. 可以切换模型或 Prompt 版本。

## 顺序原则

先做闭环，再做智能；先做可观测，再做复杂；先做可回滚，再做自动化。
