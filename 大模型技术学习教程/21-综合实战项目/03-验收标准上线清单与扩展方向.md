# 验收标准、上线清单与扩展方向

综合项目的最终验收不能只看“功能能跑”。它要同时满足产品、工程、质量、安全和运维要求。

## 功能验收

1. 文本问答可用。
2. RAG 引用可追溯。
3. 语音和图片入口可用。
4. Android 弱网、取消、重试可用。
5. 后端鉴权、限流、错误码可用。
6. 管理后台能查看知识库和基础日志。

## 质量验收

1. 评估集通过率达到阈值。
2. 失败样例有归因。
3. Prompt、模型、知识库版本可追溯。
4. 回归测试能在发布前运行。

## 安全验收

1. 客户端不暴露模型 Key。
2. RAG 检索先做权限过滤。
3. 高风险工具需要人工确认。
4. 输出不执行不可信 HTML/脚本。
5. 日志脱敏。
6. Prompt 注入红队用例通过。

## 运维验收

1. 有成本、延迟、错误率监控。
2. 有告警阈值。
3. 有灰度开关。
4. 有模型/Prompt 回滚方式。
5. 有事故复盘模板。

## 扩展方向

| 方向 | 说明 |
| --- | --- |
| Agent 工具 | 创建工单、查询业务状态 |
| Realtime 语音 | 从按住说话升级到实时对话 |
| 私有化部署 | 接入本地模型网关 |
| 多租户知识库 | 部门/客户隔离 |
| AI 编程插件 | 把知识库助手接入研发流程 |

上线不是结束，而是进入评估、反馈、优化和治理的循环。
