# 大模型技术学习教程

这套教程面向已经具备 Android、后端、前端开发经验的开发者，目标不是从机器学习研究员路线开始，而是从应用开发、工程落地、移动端场景出发，逐步掌握大模型相关技术。

你可以把它当成一条工程化路线：先能安全调用模型，再能约束输出、接入知识库和工具，最后把体验、评估、运维、安全和团队协作补齐。

## 适合谁读

这套内容默认你已经理解常规软件开发里的接口、日志、测试、鉴权、发布和客户端状态管理。它不会从微积分、深度学习框架或训练算法开始，而是用开发者熟悉的方式解释：

1. 大模型应用由哪些工程层组成。
2. 每一层解决什么问题，又解决不了什么问题。
3. Android、后端、前端分别应该承担什么职责。
4. 一个能力从 Demo 到可上线系统还缺哪些验证。

如果你的目标是做 Android 智能助手、内部知识库问答、代码 Review 助手、客服/运营助手、语音多模态应用或企业内部 AI 工具，这条路线会更贴近实际项目。

## 推荐总路线

建议按“五段式”理解 21 个阶段：

```text
基础认知与 API
  -> Prompt、结构化输出与工具调用
  -> Embedding、数据工程、RAG 与 Agent
  -> 后端、前端、Android、多模态、评估、运维、安全
  -> AI 编程、生态协议与综合项目
```

这条路线的核心原则是：先做闭环，再做智能；先做可观测，再做复杂；先做可回滚，再做自动化。

## 推荐学习方式

每个阶段都建议按这个节奏学习：

1. 先理解核心概念。
2. 再看它在 Android、后端、前端中的位置。
3. 然后写一个小 Demo 或伪代码流程。
4. 最后总结这个阶段能解决什么实际问题。

第一阶段先建立基础认知，不要求掌握数学推导，也不要求训练模型。

## 如何运行 Demo

每个含 Demo 的阶段都遵循同一种思路：`04-Demo-*.md` 解释怎么运行，`demo/` 放最小实现，`demo/tests/` 放验证用例。优先打开对应阶段的 `04-Demo` 文档，再运行里面的命令。

常见运行方式如下：

```powershell
# Python 标准库 Demo，示例：阶段 08 RAG
python '.\大模型技术学习教程\08-RAG检索增强生成\demo\rag_pipeline_demo.py' answer --question '空指针崩溃怎么排查'

# Python 测试，示例：阶段 08 RAG
python -m unittest discover -s '.\大模型技术学习教程\08-RAG检索增强生成\demo\tests'

# Node.js Demo，示例：阶段 11 前端状态机
node '.\大模型技术学习教程\11-前端与交互体验\demo\chat_ui_state.cjs'

# Java Demo，示例：阶段 12 Android 客户端状态模型
javac -encoding UTF-8 -d '.\大模型技术学习教程\12-Android端接入大模型\demo\build\classes' '.\大模型技术学习教程\12-Android端接入大模型\demo\src\AndroidAiClientDemo.java' '.\大模型技术学习教程\12-Android端接入大模型\demo\src\AndroidAiClientDemoTest.java'
```

注意：这个目录不是一个统一的工程仓库，而是一套教程资料。不要期望在根目录运行一个命令就覆盖所有语言和阶段。验证某个阶段时，请运行该阶段 `04-Demo` 文档里的命令。

## 练习与自检索引

每个阶段学完后，可以用 [阶段练习与自检](./阶段练习与自检.md) 做回顾。它把 21 个阶段都映射到同一个贯穿项目上，方便你检查自己是否真的能把概念落到 Android 知识库助手或崩溃日志分析工具里。

## 建议的第一个贯穿项目

如果你想边学边做，建议用同一个项目贯穿整套教程：

```text
Android 知识库助手 / Android 崩溃日志智能分析工具
```

它可以逐步演进：

1. 只用 Prompt 分析一段崩溃日志。
2. 加结构化 JSON 输出，方便程序消费。
3. 加知识库和引用，回答必须基于项目文档。
4. 加工具调用，读取 git diff、构建日志或接口状态。
5. 加 Android 流式 UI、取消、重试和引用展示。
6. 加评估集、成本监控、安全红队和上线门禁。

这样每个阶段学到的能力都会落到同一个系统上，而不是变成零散概念。

## 内容维护规则

大模型 API、模型价格、评估平台、MCP 生态和各供应商能力变化很快。阅读时请注意：

1. 凡是涉及模型名称、价格、接口字段、平台生命周期的内容，都以当前官方文档为准。
2. 教程里的 Demo 优先保持离线可运行，重点演示工程结构，不代表真实供应商的完整能力。
3. 如果某个阶段提到“托管能力”和“自建能力”，先理解职责边界，再决定项目里选哪一种。
4. 新增阶段或修改目录后，要确认根 README、阶段 README、章节链接和 Demo 路径都能对应起来。
